# 写一个自己的技能

技能（Skill）让萤火的 Agent 学会一件你定义的事：用固定格式写周报、按你的规矩审查代码、把对话写成流萤的旅行日记、调用你写的脚本处理文件……写好之后导入萤火，接入模型的闲聊和工作任务就能用上它。

技能的格式与 **Claude Code**、**DeepSeek Harness** 的 `SKILL.md` 相同：为它们写的技能可以直接导入萤火，反过来也一样。

> 这个仓库的 [`examples/skills/`](../examples/skills) 里有三个可以直接参考的示例，应用里「工具与技能 › 技能 › 装入示例技能」也能一键装上它们。

## 一、技能是什么

一个文件夹，里面至少有一份 `SKILL.md`：

```
my-skill/
├─ SKILL.md          必需：说明 + 步骤
├─ template.md       可选：参考资料、模板
└─ scripts/
   └─ do_it.mjs      可选：Agent 可以运行的脚本
```

`SKILL.md` 由两部分组成：开头一段 `---` 包起来的**信息头**，后面是写给 Agent 的**正文**。

```markdown
---
name: weekly-report
description: 按固定模板写工作周报。当用户要写周报、周总结或项目进展汇报时使用。
modes: [work]
---

# 周报

## 什么时候用
……

## 怎么做
1. ……
2. ……
```

## 二、信息头

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 技能名，用小写字母、数字和连字符，例如 `weekly-report`。 |
| `description` | 是 | **最重要的一句话**。Agent 一开始只看得到这句话，靠它判断要不要用这个技能，所以要写清楚「做什么」和「什么时候用」。 |
| `modes` | 否 | 在哪类任务里提供：`[chat]` 闲聊、`[work]` 工作，或 `[chat, work]`（默认两者都有）。 |
| `version` | 否 | 版本号，显示在技能列表里。 |
| `author` | 否 | 作者。 |

其他字段（例如 Claude Code 的 `allowed-tools`）会被萤火忽略，不影响导入。

## 三、正文怎么写

把 Agent 当成一个聪明但第一次接触这件事的同事：

1. **什么时候用**：列出触发场景。
2. **怎么做**：按顺序写步骤，每一步说清楚输入、输出和判断标准。
3. **用到的文件**：模板、资料、脚本的相对路径（相对 `SKILL.md` 所在的文件夹）和用法。
4. **注意**：必须遵守的规则、不能做的事。

几条经验：

- 具体胜过抽象：「标题不超过 20 字，正文分三段」比「写得简洁」有用。
- 给一个输出示例，Agent 会照着它的格式来。
- 不需要写「你是一个 AI」之类的话，萤火会处理人设和口吻。
- 正文最长约 4 万字，太长会被截断；大段资料放进单独的文件，让 Agent 需要时再读。

## 四、带脚本的技能

技能可以带脚本（Node、Python、PowerShell……），在正文里告诉 Agent 怎么运行。示例 [`word-stats`](../examples/skills/word-stats) 带了一个 Node 脚本：

```markdown
运行同一文件夹里的脚本（需要 Node.js 18 以上）：
    node "<这个 SKILL.md 所在的文件夹>/scripts/word_stats.mjs" <文件1> [文件2 …]
```

- 脚本由 Agent 用执行命令的工具运行（命令行 Agent，或带工作文件夹的 API 工作任务里萤火替模型执行的命令，后者在 Windows PowerShell 里跑），**运行前会按「工具与技能」里的策略征求你的确认**（Codex 的无头模式除外，它按沙箱执行）。
- 脚本最好只依赖系统自带的运行环境；需要第三方包的话，在正文里写清楚安装方法。
- 导入时 `node_modules` 和 `.git` 不会被复制；单个技能最多 500 个文件、20 MB。

## 五、导入与管理

打开萤火桌面版的「工具与技能 › 技能」：

- **导入技能**：选择技能文件夹（或直接选它的 `SKILL.md`）。同名技能会询问是否替换。
- **新建技能**：输入名称，萤火会生成一份带说明的 `SKILL.md` 模板并打开文件夹，改好后点「刷新」。
- **启用 / 停用**、**打开文件夹**、**删除**（移到回收站，可以恢复）。

技能保存在应用数据目录的 `skills` 文件夹里（「打开技能文件夹」可以直接打开）。

## 六、技能在运行时怎么用上

| 接入方式 | Agent 看到什么 | 能做什么 |
| --- | --- | --- |
| 命令行（Claude Code、Codex、Kimi Code…） | 每个技能的 `name`、`description` 和 `SKILL.md` 的路径 | 需要时自己读 `SKILL.md` 和资料文件，按说明运行脚本 |
| API，工作任务（有工作文件夹） | 和命令行一样：技能列表和 `SKILL.md` 的路径 | 用萤火自己的工具读 `SKILL.md` 和资料文件、运行脚本、读写工作文件夹里的文件，每一步按「工具与技能」的策略处理 |
| API，闲聊和没有工作文件夹的旧任务 | 技能正文直接放进提示词（总长约 3 万字以内，超出的只给说明） | 照着说明写作和思考；不能运行脚本、不能读写文件 |

新建闲聊或工作时，输入框下沿的「技能」标签显示这次能用的技能，可以取消勾选。

## 七、分享你的技能

- 把技能文件夹放进一个 GitHub 仓库，别人下载后在萤火里「导入技能」即可。
- 欢迎在本仓库的 [Issues](https://github.com/xtdf0224-boop/firefly-harness/issues) 里分享（标题带【技能分享】），好用的会收进 `examples/skills/`。

## 安全提醒

技能就是给 Agent 的指令，脚本会在你的电脑上运行。**只导入你信任、并且看过内容的技能**；运行脚本、写文件前留意「待确认操作」里的具体内容。
